# PRD: carrot

## 0. 문서 목적

이 PRD는 포트폴리오 시연 목적의 중고거래 플랫폼 "carrot"의 기능 요건을 정의한다. 독자는 개발팀(PM, 백엔드/프론트엔드/앱 개발자)이며, 본 문서는 UX 설계 및 아키텍처 설계의 선행 근거로 사용된다. 기술 구현 방식(DB 스키마, API 설계, 폴링 주기 등)은 `addendum.md`에 분리 기록한다.

---

## 1. 비전

carrot은 한국의 중고거래 플랫폼 "당근마켓"의 핵심 거래 흐름을 재현한 크로스플랫폼 서비스다. 판매자는 물건 사진과 설명을 올리고, 구매자는 게시글을 탐색하여 1:1 채팅으로 거래를 성사시킨다. 하나의 계정이 판매자와 구매자 역할을 모두 수행할 수 있으며, 거래 완료 후 서로 후기를 남겨 매너온도로 신뢰를 쌓는다.

위치 기반 필터링(동네 반경 제한)은 제외하며, 전국 단위 게시글 목록을 제공한다. 반응형 웹(사용자용·관리자용)과 모바일 앱(Flutter)을 단일 FastAPI 백엔드로 통합 제공한다.

## 2. 대상 사용자

### 2.1 주요 페르소나

**일반 회원 (판매자 겸 구매자)**
중고 물품을 사고팔려는 개인. 같은 계정으로 판매 게시글을 올리거나, 다른 사람의 게시글에서 구매 채팅을 시작한다. 모바일 앱과 웹 모두 사용한다.

**관리자**
서비스 운영자. 회원 계정과 거래 현황을 모니터링하고 필요 시 관리 조치를 취한다. 전용 관리자 웹을 사용한다.

### 2.2 Jobs To Be Done

- 쓰지 않는 물건을 빠르게 올리고 구매자와 협상하고 싶다
- 원하는 물건을 목록에서 찾아 판매자와 직접 소통하고 싶다
- 거래 후 신뢰할 수 있는 상대였는지 평가하고 싶다
- 운영자로서 문제 회원과 거래를 한눈에 파악하고 싶다

### 2.3 비사용자 (v1)

- 기업/사업자 판매자 (개인 간 거래만 지원)
- 결제 서비스 이용자 (직거래/계좌이체만 지원, 인앱 결제 없음)

### 2.4 핵심 사용자 여정

**UJ-1. 판매자 — 게시글 등록부터 거래완료까지**
- **페르소나 + 맥락:** 카메라를 들고 팔 물건 앞에 선 판매자
- **진입 상태:** 로그인 완료, 홈 피드
- **경로:** FAB "글쓰기" 탭 → 사진 촬영/업로드(최대 10장) → 제목·설명·가격 입력 → "작성 완료" → 게시글 게시 → 구매자 채팅 요청 수신 → 채팅방에서 상태를 "예약중"으로 변경 → 직거래 후 "거래완료"로 변경 → 구매자 후기 작성
- **클라이맥스:** "거래완료" 상태 변경 후 구매자 후기 작성 화면 노출, 매너온도 반영 확인
- **Resolution:** 판매관리 목록에서 해당 게시글이 "거래완료" 상태로 표시됨
- **엣지 케이스:** 채팅 도중 구매자가 사라지면 판매자가 상태를 다시 "판매중"으로 되돌릴 수 있다

**UJ-2. 구매자 — 게시글 탐색부터 거래완료까지**
- **페르소나 + 맥락:** 특정 물건을 찾는 구매자, 홈 피드 스크롤 중
- **진입 상태:** 로그인 완료, 홈 피드
- **경로:** 게시글 목록 탐색 → 관심 게시글 찜(좋아요) → 상세 화면 진입 → "채팅하기" 클릭 → 1:1 채팅방 생성 → 가격·거래 조율 → 직거래 완료 → 판매자가 "거래완료" 변경 후 구매자 후기 작성 가능
- **클라이맥스:** 채팅 목록에서 해당 거래가 "거래완료"로 표시, 판매자 후기 작성 화면 노출
- **Resolution:** 구매내역(나의 당근)에서 거래 내역 확인

**UJ-3. 관리자 — 회원·거래 관리**
- **페르소나 + 맥락:** 서비스 운영자, 관리자 웹 대시보드
- **진입 상태:** 관리자 계정으로 로그인
- **경로:** 회원 목록 조회 → 특정 회원 상세 → 게시글·채팅 이력 확인 → 필요 시 계정 비활성화
- **클라이맥스:** 회원 상태 변경 후 해당 계정 로그인 차단 확인
- **Resolution:** 거래관리 목록에서 해당 거래 현황 반영

## 3. 용어 정의

- **회원** — 이메일로 가입한 사용자. 판매자와 구매자 역할을 동시에 가질 수 있다.
- **판매자** — 특정 게시글의 등록자. 해당 게시글 맥락에서의 역할이며 계정 유형이 아니다.
- **구매자** — 특정 게시글에 채팅을 먼저 시작한 회원. 거래완료 시 해당 게시글의 구매자로 확정된다.
- **게시글** — 판매자가 등록한 중고 물품 정보. 사진·제목·설명·가격·상태를 포함한다.
- **거래 상태** — 게시글에 부여되는 상태값. `판매중` → `예약중` → `거래완료` 순서로 전이된다.
- **채팅방** — 특정 게시글을 기준으로 판매자 1명과 구매자 1명이 주고받는 1:1 메시지 공간.
- **매너온도** — 회원이 받은 후기를 기반으로 산출되는 신뢰 지표. 섭씨 온도 단위로 표시된다. [ASSUMPTION: 기준점 36.5℃, 긍정 후기 시 +1℃, 부정 후기 시 -1℃]
- **나의 당근** — 로그인한 회원의 개인 활동(판매관리·구매내역·관심목록)을 모아 보는 화면.
- **관리자** — 회원·게시글·채팅 전체를 열람하고 관리할 수 있는 특수 계정.

## 4. 기능

### 4.1 회원 관리

**설명:** 이메일·비밀번호 기반 회원가입과 로그인을 제공한다. 회원은 이메일(PK), 비밀번호, 주소, 연락처를 가진다. 주소는 위치 필터링에 사용되지 않으며 프로필 표시용 텍스트 필드다. [ASSUMPTION: 이메일 인증(verification) 없이 가입 즉시 활성화]

**기능 요건:**

#### FR-1: 회원가입
회원은 이메일·비밀번호·주소·연락처를 입력하여 계정을 생성할 수 있다.

**검증 조건:**
- 동일 이메일로 중복 가입 시 에러 반환
- 비밀번호는 최소 8자 이상 [ASSUMPTION]
- 가입 성공 시 JWT 발급 후 홈 피드로 이동

#### FR-2: 로그인
회원은 이메일·비밀번호로 인증하여 JWT를 발급받을 수 있다. Realizes UJ-1, UJ-2.

**검증 조건:**
- 잘못된 자격증명 입력 시 에러 메시지 반환
- 발급된 JWT는 이후 모든 인증 요청의 헤더에 포함된다

#### FR-3: 로그아웃
로그인한 회원은 클라이언트에서 JWT를 제거하여 로그아웃할 수 있다.

**검증 조건:**
- 로그아웃 후 인증 필요 화면 접근 시 로그인 화면으로 리다이렉트

#### FR-4: 회원 프로필 조회
로그인한 회원은 자신의 프로필(이메일·주소·연락처·매너온도)을 조회할 수 있다.

**검증 조건:**
- 매너온도는 소수점 1자리로 표시된다

### 4.2 게시글

**설명:** 판매자는 물품 사진(최대 10장)·제목·설명·가격을 입력하여 게시글을 등록한다. 실제 당근마켓 앱 스크린샷 기준 판매하기/나눔하기 토글, 거래 희망 장소(텍스트 입력), 임시저장을 지원한다. 모든 게시글은 전국 단위 목록에 노출된다(위치 필터링 없음). Realizes UJ-1, UJ-2.

**기능 요건:**

#### FR-5: 게시글 작성
로그인한 회원은 사진·제목·설명·가격(또는 나눔)·거래 희망 장소를 입력하여 게시글을 등록할 수 있다.

**검증 조건:**
- 사진은 최대 10장, 1장 이상 필수 [ASSUMPTION]
- 제목, 설명 필수 입력
- 가격 유형은 `판매하기`(금액 입력) 또는 `나눔하기`(무료) 중 하나
- 등록 후 게시글 상태는 `판매중`으로 초기화
- 이미지는 Supabase Storage에 업로드, URL이 게시글에 저장됨

#### FR-6: 임시저장
게시글 작성 중 회원은 임시저장할 수 있으며, 다음 작성 시 이어서 편집할 수 있다. [ASSUMPTION: 계정당 임시저장 1개]

**검증 조건:**
- 임시저장 게시글은 목록에 노출되지 않는다

#### FR-7: 게시글 목록 조회 (홈 피드)
비로그인 포함 모든 사용자는 게시글 목록을 최신순으로 조회할 수 있다.

**검증 조건:**
- 목록에는 대표 사진(첫 번째 사진)·제목·가격·상태 배지·채팅 수·관심 수가 표시된다
- 거래완료 게시글도 목록에 노출된다 [ASSUMPTION]
- 페이지네이션 또는 무한 스크롤 적용 [ASSUMPTION: 20개씩]

#### FR-8: 게시글 상세 조회
사용자는 게시글을 클릭하여 전체 정보(이미지 슬라이더·판매자 프로필·매너온도·제목·가격·설명·상태·채팅 수·관심 수·조회 수)를 조회할 수 있다.

**검증 조건:**
- 조회 수는 조회 시마다 1 증가
- 판매자 본인 게시글에서는 "채팅하기" 대신 "수정/삭제" 버튼 노출

#### FR-9: 게시글 수정
판매자는 자신의 게시글(제목·설명·사진·가격·거래 희망 장소)을 수정할 수 있다.

**검증 조건:**
- 본인 게시글만 수정 가능
- 수정 후 `updated` 타임스탬프 갱신

#### FR-10: 게시글 삭제
판매자는 자신의 게시글을 삭제할 수 있다.

**검증 조건:**
- 삭제 시 연결된 채팅방 메시지도 함께 삭제 [ASSUMPTION]
- 본인 게시글만 삭제 가능

#### FR-11: 게시글 찜 (관심)
로그인한 회원은 게시글을 찜(관심 등록/해제)할 수 있다.

**검증 조건:**
- 찜 수는 게시글 목록 및 상세에 실시간 반영
- 찜한 게시글은 나의 당근 > 관심목록에서 확인 가능

### 4.3 채팅

**설명:** 구매자가 게시글 상세에서 "채팅하기"를 누르면 해당 게시글의 판매자와 1:1 채팅방이 생성된다. 하나의 게시글에 여러 구매자가 채팅을 요청하면, 판매자에게 각각 독립된 채팅방이 생긴다. 메시지는 DB 폴링(2~3초 간격) 방식으로 수신한다. Realizes UJ-1, UJ-2.

**기능 요건:**

#### FR-12: 채팅방 생성
로그인한 회원은 자신이 판매자가 아닌 게시글에서 "채팅하기"를 눌러 채팅방을 생성할 수 있다.

**검증 조건:**
- 동일 (게시글, 구매자) 조합에 채팅방이 이미 존재하면 기존 채팅방으로 이동
- 판매자 본인 게시글에서는 채팅하기 버튼이 비활성화됨

#### FR-13: 메시지 전송 및 수신
채팅방 참여자(판매자·구매자)는 텍스트 메시지를 전송하고 수신할 수 있다.

**검증 조건:**
- 메시지는 DB에 저장되며, 클라이언트는 2~3초 폴링으로 신규 메시지를 수신한다
- 전송 실패 시 에러 표시

#### FR-14: 채팅 목록 조회
로그인한 회원은 자신이 참여 중인 채팅방 목록을 조회할 수 있다. 각 채팅방 항목에는 다음이 표시된다: 거래 게시글 대표 사진(썸네일), 상대방 이름, 마지막 메시지 내용 미리보기, 마지막 메시지 경과 시간(예: "5분 전"). Realizes UJ-1, UJ-2.

**검증 조건:**
- 최근 메시지 기준 내림차순 정렬
- 마지막 메시지 경과 시간은 상대적 표시 (1분 미만: "방금 전", 1시간 미만: "N분 전", 1일 미만: "N시간 전", 이후: "N일 전") [ASSUMPTION]
- 썸네일은 해당 채팅방과 연결된 게시글의 첫 번째 사진

#### FR-14a: 채팅 탭 미읽음 배지
새 메시지가 수신되었으나 아직 읽지 않은 채팅방이 있을 경우, 하단 탭의 "채팅" 메뉴에 미읽음 채팅방 수가 배지(+N)로 표시된다. Realizes UJ-1, UJ-2.

**검증 조건:**
- 배지 수치는 미읽음 채팅방 수 기준 (개별 메시지 수가 아님) [ASSUMPTION]
- 채팅방에 입장하면 해당 채팅방의 미읽음 상태가 해소되고 배지 수치 감소
- 미읽음 채팅방이 없으면 배지 미표시
- 배지 갱신은 채팅 목록 폴링과 동일 주기(2~3초)로 반영

### 4.4 거래 상태 관리

**설명:** 판매자는 게시글 상세 또는 채팅방 내 설정에서 거래 상태를 변경할 수 있다. 상태 전이는 `판매중 → 예약중 → 거래완료` 순서를 따르며, 판매자가 임의로 이전 상태로 되돌릴 수 있다. [ASSUMPTION: 거래완료 → 이전 상태 복구는 불가] Realizes UJ-1, UJ-2.

**기능 요건:**

#### FR-15: 거래 상태 변경
판매자는 게시글 상세 또는 채팅방에서 거래 상태를 `판매중` / `예약중` / `거래완료` 중 하나로 변경할 수 있다.

**검증 조건:**
- 판매자 본인만 상태 변경 가능
- 상태 변경 즉시 게시글 목록·상세에 배지 반영
- `거래완료`로 변경 시 구매자를 지정해야 한다 [ASSUMPTION: 현재 채팅 중인 구매자 목록에서 선택]

#### FR-16: 구매자 확정
판매자가 `거래완료`로 상태 변경 시, 해당 게시글의 구매자(회원)를 확정한다.

**검증 조건:**
- 확정된 구매자는 게시글의 `buyer_email` 필드에 저장됨
- 확정 후 양측에 후기 작성 알림 노출

### 4.5 후기 및 매너온도

**설명:** 거래완료 후 판매자는 구매자에게, 구매자는 판매자에게 후기를 작성할 수 있다. 후기는 매너온도 점수에 반영된다. [ASSUMPTION: 후기는 긍정/부정 선택 + 선택형 태그 + 선택적 텍스트로 구성] Realizes UJ-1, UJ-2.

**기능 요건:**

#### FR-17: 후기 작성
거래완료 확정 후, 판매자와 구매자 각각 상대방에 대한 후기를 1회 작성할 수 있다.

**검증 조건:**
- 동일 거래에 대해 1인 1회만 작성 가능
- 후기 작성 후 상대방의 매너온도에 즉시 반영

#### FR-18: 매너온도 표시
모든 회원의 프로필과 게시글 상세에 매너온도가 표시된다.

**검증 조건:**
- 후기가 없는 신규 회원은 기준 온도 36.5℃로 시작 [ASSUMPTION]
- 게시글 상세 화면에서 판매자 프로필 옆에 매너온도 표시

### 4.6 나의 당근 (마이페이지)

**설명:** 로그인한 회원이 자신의 활동을 모아 보는 화면. 실제 당근마켓 스크린샷 기준 판매관리·구매내역·관심목록을 포함한다. Realizes UJ-1, UJ-2.

**기능 요건:**

#### FR-19: 판매관리
회원은 자신이 등록한 게시글 목록을 상태별(판매중·예약중·거래완료)로 조회할 수 있다.

**검증 조건:**
- 각 게시글에서 상태 변경 버튼 접근 가능

#### FR-20: 구매내역
회원은 자신이 구매자로 확정된 거래완료 게시글 목록을 조회할 수 있다.

**검증 조건:**
- 목록에는 게시글 제목·대표 사진·가격·거래완료 날짜가 표시됨

#### FR-21: 관심목록
회원은 찜한 게시글 목록을 조회할 수 있다.

**검증 조건:**
- 삭제된 게시글은 관심목록에서 자동 제거 [ASSUMPTION]

### 4.7 관리자

**설명:** 관리자는 전용 웹(Next.js)을 통해 회원·게시글·채팅을 관리한다. 관리자 계정은 일반 회원과 분리된 역할(`role: admin`)을 가지며, 당근마켓에 레퍼런스가 없는 기능이므로 가입·로그인·대시보드 UI를 직접 설계·구현한다. Realizes UJ-3.

**기능 요건:**

#### FR-22: 관리자 회원가입
관리자 전용 웹에서 이메일·비밀번호로 관리자 계정을 생성할 수 있다.

**검증 조건:**
- 가입 완료 시 계정의 `role`이 `admin`으로 저장됨
- 일반 사용자 앱(Next.js 사용자용·Flutter)에서는 관리자 가입 불가 — 관리자 전용 웹 URL로만 접근 가능
- [ASSUMPTION: 별도 초대 코드 없이 관리자 전용 웹 접근 자체로 가입 허용 — 시연용]

#### FR-23: 관리자 로그인
관리자는 이메일·비밀번호로 로그인하여 대시보드에 접근할 수 있다.

**검증 조건:**
- `role: admin`이 아닌 계정으로 로그인 시 접근 거부
- 로그인 성공 시 관리자 대시보드(회원 관리 목록)로 이동

#### FR-24: 회원 관리
관리자는 전체 회원 목록을 조회하고, 특정 회원의 계정을 활성화/비활성화할 수 있다.

**검증 조건:**
- 비활성화된 회원은 로그인 불가 (JWT 발급 거부)
- 목록에는 이메일·가입일·매너온도·게시글 수가 표시됨

#### FR-25: 거래 관리
관리자는 전체 게시글 목록을 조회하고 상태를 확인할 수 있다.

**검증 조건:**
- 상태별 필터(판매중·예약중·거래완료) 제공
- 관리자는 게시글을 강제 삭제할 수 있다 [ASSUMPTION]

#### FR-26: 채팅 관리
관리자는 전체 채팅 내역을 조회할 수 있다.

**검증 조건:**
- 채팅방 목록에서 (판매자, 구매자, 게시글) 조합과 메시지 수 표시
- 특정 채팅방의 메시지 내역 열람 가능

## 5. 명시적 Non-Goals (v1)

- **위치 기반 필터링** — 동네 반경 기반 게시글 노출 없음. 전국 단위 목록만 제공.
- **인앱 결제 / 바로구매** — 직거래·계좌이체만 지원. 결제 시스템 없음.
- **커뮤니티 피드** — 동네 소식, 커뮤니티 게시판 없음.
- **동네지도** — 지도 기반 UI 없음.
- **키워드 알림 / 푸시 알림** — 실시간 알림 시스템 없음.
- **신고 처리 워크플로우** — 신고 접수 UI만 제공; 관리자 전용 처리 프로세스 없음. [NON-GOAL for MVP]
- **내 물건 가격 찾기 / 중고거래 가계부** — 당근마켓 부가 기능 제외.
- **소셜 로그인** (카카오·네이버·구글) — 이메일/비밀번호만 지원.
- **단골 목록 / 팔로우** — 사용자 간 구독 관계 없음.

## 7. 성공 지표

포트폴리오·시연 목적이므로 기능 완성도와 시연 가능성이 주요 기준이다.

**Primary**
- **SM-1:** 판매자 시나리오(가입→게시→채팅→거래완료→후기) 전체 흐름이 에러 없이 시연 가능. Validates FR-1, FR-5, FR-12~16, FR-17.
- **SM-2:** 구매자 시나리오(가입→게시글 탐색→채팅→거래완료→후기) 전체 흐름이 에러 없이 시연 가능. Validates FR-2, FR-7~8, FR-12~14, FR-17.
- **SM-3:** 관리자 시나리오(가입→로그인→회원 비활성화→거래 목록 확인) 시연 가능. Validates FR-22~FR-26.

**Secondary**
- **SM-4:** 웹(Next.js)과 모바일 앱(Flutter)에서 동일 계정으로 로그인 및 핵심 기능 동작. Validates FR-2.
- **SM-5:** 두 계정이 동시에 채팅방에서 메시지를 주고받을 때 3초 이내 수신. Validates FR-13.

**Counter-metrics (최적화 금지)**
- **SM-C1:** 채팅 폴링 주기 단축을 위해 서버 부하를 늘리지 않는다. SM-5 달성을 위해 폴링 간격을 1초 미만으로 낮추는 것은 금지.

## 9. 비기능 요건 (Cross-cutting NFRs)

- **인증:** 모든 인증 필요 API는 JWT Bearer 토큰 검증 (FastAPI 미들웨어). 토큰 만료 시 401 반환.
- **이미지 업로드:** Supabase Storage Presigned URL 방식. 클라이언트가 직접 업로드, 서버는 URL만 수신·저장. 이미지당 최대 5MB [ASSUMPTION].
- **채팅 폴링:** 클라이언트는 2~3초 간격으로 신규 메시지를 조회. 서버는 표준 GET 엔드포인트로 응답.
- **CORS:** 사용자 웹·관리자 웹·Flutter 앱 도메인에 대해 허용 오리진 명시.
- **응답 속도:** 게시글 목록 API p95 응답 2초 이내 [ASSUMPTION: MVP 기준 동시 사용자 소수].
