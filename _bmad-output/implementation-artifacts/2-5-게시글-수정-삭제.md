# Story 2.5: 게시글 수정 & 삭제

Status: done

## Story

As a 로그인한 판매자,
I want to edit or delete my own posts,
so that I can keep my listings accurate or remove them when sold.

## Acceptance Criteria

1. 판매자 본인이 `PATCH /api/v1/posts/{post_id}`로 수정 요청을 보내면 제목·설명·사진·가격·거래 희망 장소가 업데이트되고 `updated_at`이 갱신된다 (JWT 필요)
2. 타인(또는 비로그인)이 PATCH/DELETE를 시도하면 `{"detail": "권한이 없습니다.", "code": "FORBIDDEN"}` 403 에러가 반환된다
3. 판매자 본인이 `DELETE /api/v1/posts/{post_id}`를 호출하면 Supabase Storage 이미지 파일이 먼저 삭제된 후 DB 레코드가 삭제된다 (FK CASCADE로 likes, chat_messages 포함)
4. Next.js `/posts/[id]/edit` 페이지에서 기존 내용이 pre-populate된 수정 폼이 표시되고 저장 성공 시 `/posts/[id]`로 이동한다
5. Next.js 게시글 상세 페이지 삭제 버튼 클릭 시 확인 다이얼로그 후 삭제 → 홈 피드(`/`)로 이동한다
6. Flutter 게시글 상세 화면에서 수정 버튼 탭 시 PostEditScreen으로 이동하고 삭제 버튼 탭 시 확인 다이얼로그 후 삭제 → 홈 피드로 이동한다

### PATCH UpdatePostRequest — 부분 수정 스키마

```python
# app/features/posts/schemas.py 추가
class UpdatePostRequest(BaseModel):
    title: str | None = Field(default=None, max_length=100)
    description: str | None = Field(default=None, max_length=2000)
    price: int | None = Field(default=None, ge=0)
    is_free: bool | None = None
    trade_place: str | None = None
    photos: list[str] | None = Field(default=None, max_length=10)

    @model_validator(mode="after")
    def price_none_when_free(self) -> "UpdatePostRequest":
        if self.is_free and self.price is not None:
            raise ValueError("나눔 게시글은 price를 설정할 수 없습니다.")
        return self
```

> `photos` 필드에 `None`을 보내면 사진을 변경하지 않고 유지. 빈 배열 `[]`을 보내면 PHOTO_REQUIRED 에러 (최소 1장 유지).
> 단, 수정 시 photos 최소 1장 검증은 **service 레이어**에서 처리.

### carrot-api: _get_owned_post (service private helper)

```python
async def _get_owned_post(
    db: AsyncSession,
    post_id: int,
    seller_email: str,
) -> Post:
    post = await repository.get_post_by_id(db, post_id)
    if post is None:
        raise AppException(code="POST_NOT_FOUND", detail="게시글을 찾을 수 없습니다.", status_code=404)
    if post.seller_email != seller_email:
        raise AppException(code="FORBIDDEN", detail="권한이 없습니다.", status_code=403)
    return post
```

### carrot-api: repository.update_post

```python
async def update_post(db: AsyncSession, post: Post, request: "UpdatePostRequest") -> Post:
    if request.title is not None:
        post.title = request.title
    if request.description is not None:
        post.description = request.description
    if request.price is not None or (request.is_free is True):
        post.price = None if request.is_free else request.price
    if request.is_free is not None:
        post.is_free = request.is_free
    if request.trade_place is not None:
        post.trade_place = request.trade_place
    if request.photos is not None:
        post.photos = request.photos
    try:
        await db.commit()
        await db.refresh(post)
    except IntegrityError as e:
        await db.rollback()
        raise AppException(code="POST_UPDATE_FAILED", detail="게시글 수정에 실패했습니다.", status_code=422) from e
    return post
```

> `trade_place=None`으로 보내도 None은 "변경하지 않음"으로 처리. 명시적으로 비우려면 별도 처리 필요하지만 이 스토리 scope에서는 None=유지로 단순화.

### carrot-api: DELETE router — Supabase Storage 파일 경로 추출

```python
@router.delete("/{post_id}", status_code=204)
async def delete_post(
    post_id: int = Path(ge=1),
    current_user: dict = Depends(get_current_user),
    db: AsyncSession = Depends(get_db),
) -> None:
    seller_email = current_user.get("sub")
    if not seller_email:
        raise AppException(code="UNAUTHORIZED", detail="유효하지 않은 토큰입니다.", status_code=401)
    photos = await service.delete_post(db, seller_email, post_id)
    # Supabase Storage 파일 삭제
    if photos:
        file_paths = []
        for url in photos:
            if f"/storage/v1/object/public/{_BUCKET}/" in url:
                path = url.split(f"/storage/v1/object/public/{_BUCKET}/")[-1]
                file_paths.append(path)
        if file_paths:
            try:
                _supabase.storage.from_(_BUCKET).remove(file_paths)
            except Exception:
                pass  # Storage 삭제 실패해도 DB 삭제는 완료됨
```

> Storage 삭제 실패는 무음 처리 — DB에서 이미 삭제됐으므로 orphan 파일 발생. 포트폴리오 scope에서는 허용.
> 204 반환 시 `return` 또는 `return None`만 하면 됨 (FastAPI가 body 없이 204 반환).

### carrot-mobile: ApiClient.delete 확인

`api_client.dart`에 `delete(path)` 메서드가 있음:
```dart
Future<dynamic> delete(String path) async { ... _handleResponse(res) }
```
단, 204 No Content 응답 시 body가 없으므로 `jsonDecode('')` 오류 발생 가능.
`deletePost`에서 204 응답 처리:

```dart
Future<void> deletePost(int id) async {
  // ApiClient.delete는 _handleResponse를 통해 jsonDecode 시도 → 204시 빈 body
  // 두 가지 처리:
  // 1) ApiClient에 deleteNoContent 메서드 추가
  // 2) try-catch로 FormatException 무시
  try {
    await _client.delete(ApiEndpoints.postDetail(id));
  } on FormatException {
    // 204 No Content — 정상 응답
  }
}
```

> `api_client.dart`의 `_handleResponse`는 `jsonDecode(utf8.decode(res.bodyBytes))`를 항상 호출함.
> 204 응답 시 body가 빈 문자열이므로 `FormatException` 발생 → 무시하면 됨.
