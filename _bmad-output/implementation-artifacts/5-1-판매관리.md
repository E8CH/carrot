# Story 5.1: 판매관리

Status: done

## Story

As a 판매자,
I want to see all my posts filtered by status,
so that I can track and manage my active and completed listings.

## Acceptance Criteria

1. 로그인한 회원이 `GET /api/v1/users/me/posts`를 호출하면 내 게시글 전체 목록이 반환된다
2. `?status=판매중|예약중|거래완료` 쿼리 파라미터로 상태 필터링이 가능하다
3. 유효하지 않은 status 값이면 422 에러가 반환된다
4. 각 항목에 `id, title, price, is_free, status, thumbnail, chat_count, like_count, created_at`이 포함된다 (기존 `PostListItem` 스키마 재사용)
5. Next.js 나의 당근 페이지(`/my`)에 판매관리 섹션이 추가된다 — 상태 필터 탭(전체/판매중/예약중/거래완료) + 게시글 목록
6. 각 게시글에 상태 변경 버튼이 표시된다 (판매중↔예약중 인라인 토글; 거래완료 게시글은 버튼 없음)
7. Flutter 나의당근 탭에도 동일한 판매관리 섹션이 추가된다

### Task 1-4: Backend 구현 가이드

**`posts/repository.py` `get_my_posts` 패턴:**

기존 `get_posts` 함수(line 14~46)와 동일한 서브쿼리 패턴 사용:

```python
async def get_my_posts(
    db: AsyncSession, seller_email: str, status: str | None
) -> tuple[list, int]:
    like_count_sq = (
        select(func.count(Like.id))
        .where(Like.post_id == Post.id)
        .correlate(Post)
        .scalar_subquery()
    )
    chat_count_sq = (
        select(func.count(ChatMessage.id))
        .where(ChatMessage.post_id == Post.id)
        .correlate(Post)
        .scalar_subquery()
    )

    filters = [Post.seller_email == seller_email, Post.is_draft == False]  # noqa: E712
    if status is not None:
        filters.append(Post.status == status)

    stmt = (
        select(Post, like_count_sq.label("like_count"), chat_count_sq.label("chat_count"))
        .where(*filters)
        .order_by(Post.updated_at.desc())
    )
    rows = (await db.execute(stmt)).all()
    return rows, len(rows)
```

const handleStatusChange = async (id: number, newStatus: string) => {

  try {
    await postsApi.changeStatus(id, newStatus)

}
